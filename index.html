autocomplete.js — pseudocodeTRIE
function autocomplete(prefix) {
  node = trie.root

  for each letter in prefix:
    if letter not in node.children:
      return []
    node = node.children[letter]

  return node.topSuggestions
}
THE CORE IDEA

Search only the letters you need.

Unlike a normal list that checks words one by one, a Trie gives every letter its own path. Each node stores its top 8 suggestions, already sorted by popularity.

Once the prefix is found, the best suggestions are already waiting there. This is called cached top-K retrieval.

*Building/updating the Trie takes extra work and memory, so that live lookups can be fast.
04 ALGORITHM DESIGNS AND COMPLEXITY

Smarter structure. Faster search.

Why we chose a Trie instead of scanning every word in a list.

NAIVE LINEAR SEARCHCHECKS ALL WORDS
O(N × P)

For each of the N dictionary words, check whether it starts with the P-letter prefix. Ranking results adds extra work.

OUR TRIE APPROACHPREFIX LOOKUP
O(P + K)

Follow P characters through Trie nodes, then display up to K precomputed suggestions. No full dictionary scan during lookup.

OperationSimple arrayOur TrieEasy meaning
Find prefixO(N × P)O(P)Walk the typed letters
Return suggestionsRanking can add workO(K)Read the stored top K words
Insert one wordO(1) append*O(L × K log K)Update cached suggestions along L letters
MemoryO(total characters)More: nodes + top-K cachesTrading memory for speed

N = number of words; P = prefix length; K = maximum suggestions (8); L = inserted word length. *Append excludes any indexing or ranking work. With fixed K = 8, insertion is effectively O(L). Our demo rebuilds its Trie when frequencies or dictionary entries change.
